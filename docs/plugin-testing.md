# Plugin beta testing

Use the local signed catalogue generated by `../craft-extensions/scripts/e2e.sh`.
Wait for that script to finish before refreshing; it republishes the catalogue while testing.
Commands below run from the PhotoCraft repository and use a disposable store.
All builds are debug builds and share the resource lock with the other apps.

```sh
flock /home/ash/projects/plugin-beta/.cargo.lock env CARGO_BUILD_JOBS=4 cargo build -p photocraft-cli
export CRAFT_EXT_DIR="$(mktemp -d /tmp/photocraft-plugin-beta.XXXXXX)"
export CRAFT_CATALOGUE_URL=file:///home/ash/projects/plugin-beta/test-catalogue/
export CRAFT_CATALOGUE_ALLOW_FILE=1
export PHOTOCRAFT_CRAFT_EXT_BIN=/home/ash/projects/plugin-beta/craft-extensions/target/debug/craft-ext
CLI=./target/debug/photocraft-cli
HALF=io.github.arnav-hiwarkar.halftone
FILM=io.github.arnav-hiwarkar.film-looks
$CLI plugin refresh
$CLI plugin search halftone
$CLI plugin search film-looks
$CLI plugin install "$HALF"
$CLI plugin setup "$HALF" --all
$CLI plugin install "$FILM"
$CLI plugin setup "$FILM" --all
$CLI commands --filter plugin --json
$CLI plugin contract > /tmp/photocraft-contract.md
diff -u ../craft-extensions/docs/plugins/contracts/photocraft.md /tmp/photocraft-contract.md
```

Halftone 1.0.0 is selected; the catalogue's incompatible 2.0.0 is intentionally excluded.
Install does not enable contributions. These two packages need no grants.

Run the focused adapter and installed-package acceptance tests:

```sh
flock /home/ash/projects/plugin-beta/.cargo.lock env CARGO_BUILD_JOBS=4 cargo test -p photocraft-plugins --lib
flock /home/ash/projects/plugin-beta/.cargo.lock env CARGO_BUILD_JOBS=4 PHOTOCRAFT_PLUGIN_BETA_TEST=1 cargo test -p photocraft-engine --test plugin_beta -- --ignored --nocapture
```

The installed-package test requires the disposable store above. It checks 8/32-bit changed
pixels, exactly one undo step, undo/redo, invalid form values, matching film-looks presets,
CMYK/Lab refusal, LUT discovery and loading through Color Lookup, permission epoch revocation,
and kill-list refusal without changing the document. It packs and installs a synthetic Wasm
session command, runs it through `Session::execute`, and verifies its rename and undo step.
It clears its synthetic kill list at the end; do not run it on a personal store.
After that test installs the fixture, verify the CLI session route:

```sh
$CLI run --new '{"width":4,"height":4}' \
  --cmd plugin.session.io.test.photocraft-session/rename --out /tmp/photocraft-session.pcraft
$CLI info /tmp/photocraft-session.pcraft
```

The saved layer must be named “Plugin renamed”.

Exercise CLI application, native saving and PNG export (do not overwrite source images):

```sh
mkdir -p /tmp/photocraft-plugin-output
for depth in 8 32; do
  $CLI run --new "{\"width\":32,\"height\":32,\"depth\":$depth,\"background\":\"#806040\"}" \
    --out "/tmp/photocraft-plugin-output/input-$depth.png"
  $CLI run --new "{\"width\":32,\"height\":32,\"depth\":$depth,\"background\":\"#806040\"}" \
    --cmd "plugin.$HALF/halftone" --params '{"size":6,"angle":45,"mono":true}' \
    --out "/tmp/photocraft-plugin-output/halftone-$depth.pcraft"

    --out "/tmp/photocraft-plugin-output/halftone-$depth.png"

$CLI run --new '{"width":4,"height":4,"mode":"cmyk"}' --cmd "plugin.$HALF/halftone"
$CLI run --new '{"width":4,"height":4,"mode":"lab"}' --cmd "plugin.$HALF/halftone"
```

The last two commands must fail with “This filter works on RGB images”. The acceptance
test compares actual surface samples; visually compare the exported PNGs as well.

Build the desktop binary after completing headless checks:


For manual GUI testing, launch `./target/debug/photocraft` from the same environment so it
uses this store and catalogue. No GUI launch is part of the headless acceptance procedure.
Open a photo, then Filter → Plugins → Stylize → Halftone. Change Dot size, Grid angle and
Black and white; select “Halftone print” and “Colour halftone” from the presets. Apply,
check one “Halftone · Halftone” entry in History, Undo and Redo, then save a `.pcraft`
and export PNG. Repeat in RGB 32-bit mode. CMYK and Lab must disable the filter with the
RGB reason. Layer masks, channels and Quick Mask also show their refusal reason.

In Image → Adjustments → Color Lookup, find “From plugins / Film warm”; repeat with a
Color Lookup adjustment layer. Allow two seconds for asynchronous resource discovery.
Open the Plugins manager to disable/re-enable Halftone and verify the filter menu follows.
The test's “Session acceptance → Rename” command also appears under Plugins; use it on a
pixel layer, check the layer name “Plugin renamed”, and Undo.

The renderer remains egui; `plugin_form::draw` is the form widget seam for a future renderer.
No craft-framework integration is required for this beta.

## Durable LUT references

Plugin LUT pickers return `plugin://<id>/<contribution>/<file>` references. Color Lookup
adjustment layers keep that reference in their name alongside the embedded table. Reopening
resolves the active plugin release; update and rollback do not require choosing the file again.
If the plugin is missing or disabled, opening reports “needs plugin …” and retains both the
reference and embedded table for a later save. Preset recipes store their applied values inline.

```sh
LUT="plugin://$FILM/film-warm/luts/film-warm.cube"
$CLI run --new '{"width":16,"height":16,"background":"#806040"}' \
  --cmd layer.newAdjustmentLayer.colorLookup --params "{\"file\":\"$LUT\"}" --out /tmp/plugin-lut.pcraft
$CLI run /tmp/plugin-lut.pcraft --out /tmp/plugin-lut-before.png
$CLI plugin update "$FILM"
$CLI run /tmp/plugin-lut.pcraft --out /tmp/plugin-lut-updated.png
$CLI plugin rollback "$FILM" 1.0.0
$CLI run /tmp/plugin-lut.pcraft --out /tmp/plugin-lut-rollback.png
```
